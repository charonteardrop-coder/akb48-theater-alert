# AKB48 THEATER ALERT

推しメンが出るAKB48劇場公演の**受付が始まったら、スマホにプッシュ通知**するウェブアプリ（非公式・ファンメイド）。
情報源は **AKB48チケットセンター（akb48.zaiko.io）だけ**。アプリストアを通さず、ホーム画面に追加して使う。

## ファンの使い方

1. サイトを開く（iPhoneはSafari）
2. iPhoneは **共有ボタン →「ホーム画面に追加」** → ホーム画面の「AKB48 ALERT」から開く（iOS 16.4以降）
   Android・PCはそのままでOK
3. 推しを選んで「通知をオンにする」→ 許可

推しを選び直すと自動でサーバーに反映される。「全公演の受付開始を受け取る（箱推し）」も選べる。

## 届く通知

| いつ | 例 | タップすると |
|---|---|---|
| 推しが出る公演の受付が始まった | 🎫 千葉恵里 出演公演の受付が始まったよ<br>11/17(火) 18:30 「ＲＥＳＥＴ」公演（千葉恵里 生誕祭）<br>〆 11/10(火) 16:00 映像倉庫/柱の会/100発98中<br>〆 11/12(木) 16:00 一般/ファミカプ/女性・小中学生 | アプリ内のその公演 →「チケットセンターで申し込む」 |
| メンバー変更で推しが出演することになった | 🔄 山﨑空 がメンバー変更で出演決定 | 同上 |
| 推しが出演者から外れた | ℹ️ ○○ が出演メンバーから外れたよ | 同上 |
| 受付中の締切の6時間前 | ⏰ 推しの出演公演、締切が近いよ | 同上 |

- 推しが複数いても、1回のチェックで同じ種類の通知は1通にまとめる
- Androidでは通知に「申し込む」ボタンが付く（iPhoneはウェブ通知のボタン非対応なので本文タップのみ）
- 「受付開始」はロビー観覧以外の枠のどれかが受付中になったとき。締切はチケットセンターに登録された各枠の実際の受付終了日時

## 観覧記録

ページ下の「観覧記録」で、行った公演を記録できる。

- **日付を選ぶ → その日の公演**：日付を選ぶと、その日の劇場公演が出てくる（2回公演の日は選べる）。選ぶと開演・演目（チーム名つき）・生誕祭などの補足・出演メンバーが自動で入る。公演一覧の「行った！」ボタンからも記録できる（開演後の公演に出る）
- **過去公演のデータ**：2012年〜の約5,000公演を `docs/data/history/年.json` に同梱（公式ブログ「劇場情報」から取り込み、メンバー変更のお知らせも反映済み）。最近の公演はチケットセンターのデータ（`archive.json`）が優先される
- **手入力**：データがない日（2012年より前など）や、取り込みで拾えなかった公演用。卒業生も「メンバーを追加」から選べる
- **記録できる項目**：日付・開演・演目・補足・出演メンバー・当選した枠・メモ（座席や感想）・写真
- **写真**：1公演20枚まで。長辺1600pxのJPEGに縮小して端末のIndexedDBに保存。カードのサムネをタップで全画面表示、そこから保存・共有できる
- **集計**：通算／今年／推しが出てた公演数／観たメンバー数、推しを見た回数、演目別の回数
- **保存先はその端末の中だけ**（サーバーには送らない）。ホーム画面のアイコンを消すと消えるので、「書き出す」でバックアップ（JSONファイル、写真も込み）を取って、「読み込む」で戻せる。同じファイルを何度読んでも重複しない

## 過去公演データについて

- 公式ブログ「劇場情報」テーマの記事（2012年〜・約5,000件）を読み取って作っている。書き方が時代ごとに違う（チーム公演時代の「公演メンバーのお知らせ」、「出演メンバーとお申し込みについて」、今の「受付開始のお知らせ」「公演のご案内」など）ので、それぞれに対応している
- メンバー変更（「【休演】【出演】」「休演：○○」「○○ ⇒ △△」「出演予定でした○○ですが…代わりに△△が出演」など）も時系列で反映
- 2026年11月時点の取り込み結果：4,951公演（メンバーつき約94%、演目名つき99.8%）。ブログ側の誤字（メンバー名の誤記など）はそのまま
- 作り直したいときは Actions →「過去公演の取り込み」→ Run workflow（1〜2時間かかる。2025年以降はチケットセンターの最終メンバーで上書きもする）。中身は `scripts/import-history.js`

## しくみ

```
┌ GitHub Actions（10分おき）───────────────────────────┐
│ 1. akb48.zaiko.io のトップを読む（公演・出演者・枠の状態）  │
│ 2. 変化があった公演だけ詳細ページで受付期間を読む           │
│ 3. 通知が必要なら、購読サーバーから購読一覧をもらって         │
│    購読者ごとに文面を作り Web Push で送信（失効分は削除依頼） │
│ 4. docs/data/*.json を更新してコミット → GitHub Pages に反映 │
│    （一覧から消えた終了公演は archive.json に移す）          │
└───────────────────────────────────────────────┘
┌ 購読サーバー（Cloudflare Workers + D1）┐   ┌ サイト（GitHub Pages）────────┐
│ どの端末がどの推しを購読しているかを保存 │ ← │ 推し選択・通知オン/オフ・公演一覧 │
└───────────────────────┘   │ service worker が通知を表示     │
                                       └───────────────────┘
```

| フォルダ | 中身 |
|---|---|
| `src/` | チェックと送信（GitHub Actionsで動く） |
| `worker/` | 購読サーバー（Cloudflare Workers） |
| `docs/` | サイト本体（GitHub Pagesで公開）。`sw.js` が通知担当 |
| `test/` | テスト（チケットセンターの実データ入り） |

## セットアップ（30〜40分）

必要なもの：GitHubアカウント、Cloudflareアカウント（無料）、Node.js 22以上

### 1. 鍵を作る

```bash
npm install
npx web-push generate-vapid-keys   # Public Key と Private Key が出る
openssl rand -hex 24               # ADMIN_TOKEN 用のランダム文字列
```

### 2. GitHubに上げてPagesを有効化

1. このフォルダを公開リポジトリとして push
2. Settings → Pages → Source「Deploy from a branch」→ `main` / `/docs`
3. サイトのURL（例 `https://yourname.github.io/oshi-alert/`）をメモ

### 3. 購読サーバーをCloudflareに置く

```bash
cd worker
npx wrangler login
npx wrangler d1 create oshi-gekijo-alert           # 表示された database_id を wrangler.toml に貼る
npx wrangler d1 execute oshi-gekijo-alert --remote --file=schema.sql
npx wrangler secret put ADMIN_TOKEN                 # 1で作ったランダム文字列
```

`wrangler.toml` の `ALLOWED_ORIGINS` をサイトのオリジン（例 `https://yourname.github.io`）に変えてから：

```bash
npx wrangler deploy        # https://oshi-gekijo-alert.<あなた>.workers.dev が出る
```

### 4. GitHub Actionsの設定

Settings → Secrets and variables → Actions

| 種類 | 名前 | 値 |
|---|---|---|
| Variables | `API_BASE` | 3のWorkerのURL（末尾の `/` なし） |
| Variables | `VAPID_PUBLIC_KEY` | 1の Public Key |
| Variables | `VAPID_SUBJECT` | `mailto:あなたのメール` |
| Secrets | `VAPID_PRIVATE_KEY` | 1の Private Key |
| Secrets | `ADMIN_TOKEN` | 1のランダム文字列（Workerと同じ） |
| Variables（任意） | `REMINDERS` | `0` で締切リマインドを止める |

### 5. 初回実行

Actions →「劇場公演チェック」→ Run workflow。初回は今載っている公演のデータを作るだけで通知は送らない。
終わったらサイトを開いて、自分のiPhoneで通知をオンに →「表示テスト」で見え方を確認。

## 手元で試す

```bash
npm test                                   # 実データでの解析・文面・購読サーバー・暗号化・通しの動作
DRY_RUN=1 node --no-warnings src/run.js    # 実際にチケットセンターを読む（送信はしない）
```

## 気をつけること

- **非公式ツール**。チケットセンター（ZAIKO）のページ構造が変わると読めなくなる。そのときはActionsのログにエラーが出るので `src/zaiko.js` を直す
- 通知は「チケットセンターに載った・変わった」タイミング。公式ブログやXでの発表が先に出ることもある
- トップページに載る公演数に上限があるかは未確認（2026/11/10時点で10件すべて表示）。公演が多い時期はログで取りこぼしがないか見てね
- 自動購入はしない。通知からチケットセンターに飛ぶところまで
- **メンバーの並び順（先輩順）は `docs/data/roster.json` の順番**。AKB48公式サイトのメンバー一覧の掲載順と期を入れてある（2026/11/10時点・49人）。新メンバーの加入や卒業があったら手で更新してね。表にない名前がチケットセンターに出てきたら、プルダウンの「その他」に並ぶ（通知はちゃんと届く）
- iPhoneはホーム画面のアイコンを消すと購読も消える。通知の許可はiPhoneの「設定 → 通知 → AKB48 ALERT」で変えられる
- 購読サーバーには端末ごとの通知先URL・暗号鍵と選んだ推しの名前だけを保存する（名前やメールなどの個人情報は扱わない）
- GitHub Actions・Cloudflare Workers・D1・GitHub Pages はいずれも無料枠で動く規模。利用者がとても増えたら各サービスの上限を確認
- 公開リポジトリで60日間まったく動きがないと定期実行が止まる。データ更新のコミットが入るので普段は大丈夫だけど、止まっていたら Actions から再開
